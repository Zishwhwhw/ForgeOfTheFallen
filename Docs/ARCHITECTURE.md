# Forge of the Fallen — архитектура

Версия 1.0 · 26.11.2026. Принято: правила A1–A9, G6–G7 (`Research/RULES_DIGEST.md`), п.141 (сцены), п.151 (серая коробка на целевой архитектуре).
Изменения этого файла — только с согласия владельца, запись в `Docs/DECISIONS.md`.

## 1. Стек
- Unity 6 (6000.x), Universal 2D (URP 2D), C#.
- Input System, 2D Tilemap (+ Extras), 2D Sprite, 2D Animation по необходимости, URP 2D Lights.
- Unity Test Framework (EditMode — логика, PlayMode — дымовые тесты сцен).
- Unity Localization (RU / EN / PL).
- Остальные пакеты и плагины — только через `Docs/DECISIONS.md` с лицензией.

## 2. Слои (data-driven)
```
Input ──► Logic ◄── Data (ScriptableObject, только чтение)
            │
            ├──► State / Save (runtime-модели, сериализуемые)
            ├──► Utils (Steam, локализация, загрузка, RNG, время)
            └──► View (префабы на сцене: спрайты, анимации, VFX, SFX, UI)
                    ▲
Игрок видит View и снова даёт Input
```

| Слой | Что | Правила |
|---|---|---|
| **Data** | `ScriptableObject`-описания: оружие, враги, пассивки, статусы, комнаты/чанки, лут-таблицы, проклятия, цены, герои, баланс | Только данные, без логики. В игре не меняются. У каждого объекта стабильный `Id` (строка, `weapon.eternal_sword`). Числа контента живут только здесь |
| **Logic** | Чистый C# (без `MonoBehaviour`, где можно): урон, броня, статусы, сплав, лут, экономика, волны, генератор графа | Читает Data, пишет State, сообщает View через события. Детерминирован от seed. Покрывается EditMode-тестами |
| **State / Save** | Runtime-модели: HP, броня, мана, инвентарь, пассивки, проклятия, прогресс забега, мета (кристаллы, открытые герои, дневник сплавов) | Отдельно от Data (A3). Сериализация в JSON. В срезе — только мета-сейв; сейв между этажами — 1.0 |
| **Input** | Input System actions → команды (`Move`, `Aim`, `Fire`, `Dash`, `Swap`, `Interact`, `Skill`, `Ultimate`, `Bomb`) | Input не трогает объекты сцены напрямую, только команды в Logic (A5). Схема сразу под 2–4 игроков (п.58), в срезе 1 |
| **View** | `MonoBehaviour` на префабах: отображают State, проигрывают анимации, VFX, SFX, UI | Не принимают игровых решений (A4). Можно заменить арт без правки Logic (A9) |
| **Utils** | Локализация, RNG с seed, сервис времени, загрузка сцен, Steam (1.0) | Без игровой логики |

## 3. Сцены и префабы (п.141, G7)
- **Всё, что видно, собрано в редакторе** и правится в Inspector: сцены, префабы, Tilemap, коллайдеры, точки спавна, UI.
- Код **только инстанцирует готовые префабы** по правилам (генератор, волны, лут). Код не строит сцены, UI или объекты из примитивов в `Start()`/`Awake()`.
- Готовые сцены: `Boot`, `Refuge` (хаб — пещера-оазис), `Prologue`, `Run` (контейнер этажа), `Boss_Golem`, ориентиры биома.
- Префабы: герои, враги, оружие (база + слои гибрида), снаряды, сундуки, кузница, торговец, двери, портал, **чанки комнат 8×8 тайлов**, спец-комнаты.
- Чанк — префаб с Tilemap + метаданными (`ChunkDefinition`: теги биома, угрозы, точки входа, точки спавна волн).

## 4. Генерация этажа (п.41, A7)
1. Logic строит граф этажа по seed и правилам биома, проверяет гарантии (GDD §8.2).
2. Для каждого узла выбирается шаблон комнаты: ручной префаб (спец-комната, ориентир) или сборка из чанков.
3. View/RunBuilder инстанцирует префабы в сцене `Run`.
4. Без random walk и глобального BSP.

## 5. Сплав (GDD §6)
- `FusionService` (Logic): вход — два `WeaponInstance`, seed; выход — новый `WeaponInstance` с доминантой A/B/середина, смешанными статами, флагом джекпота.
- Визуал гибрида — `WeaponView` собирает слои: база более редкого + деталь второго + цвет элемента + слой швов.
- Дневник сплавов — часть мета-State.

## 6. Папки
```

  _Project/
    Data/            ScriptableObject-ассеты (Weapons/, Enemies/, Passives/, Rooms/, Chunks/, Loot/, Heroes/, Balance/)
    Scripts/

      State/         runtime-модели и сериализация
```

Assembly Definitions: `FotF.Data`, `FotF.Logic`, `FotF.State`, `FotF.View`, `FotF.Tests.*`. Logic не ссылается на View.

## 7. Правила для агентов (код)
- Не создавать новую систему, не проверив существующие (A1); не дублировать (G6).
- Числа контента — только в Data (A2, A8, G6).
- Новая механика — сначала план (B3), потом код маленькой поставкой (B4).
- После изменений: компиляция без ошибок, Unity Console чистая, EditMode-тесты зелёные (B14). Финальное «готово» — после плейтеста владельца (G3).
- Нерешённый дизайн — вопрос владельцу, а не выдумка (G4, C20).
- Не коммитить `Library/`, `Temp/`, `Logs/`, `UserSettings/`, IDE-файлы.

## 8. Баланс из Google Таблиц и сейвы (решение владельца 27.11.2026, ◆ схема Claude — ждёт реализации)
Цель: все настраиваемые числа (оружие, враги, герои, пассивки, статусы, лут, цены, волны, сплав, game feel) правятся в Google Таблице, а не в коде и не руками в Inspector.

### 8.1 Поток данных
```
Google Таблица «FotF Balance» (источник истины для чисел)
   │  Tools/data/sheets_to_json.py   — скачивает вкладки, валидирует, пишет JSON
   ▼
Assets/_Project/Data/Balance/*.json  — в git, отсортировано, диффается в PR
   │  Editor: «FotF/Данные/Импорт баланса» (+ авто при изменении .json)
   ▼
ScriptableObject-ы (Data-слой, §2)    — числа перезаписаны по Id, ссылки на спрайты/префабы не трогаются
   │  сборка игры
   ▼
Игрок: игра читает SO. Сеть, Google и JSON-парсинг баланса в рантайме не нужны.
```
- **Не грузим таблицу из игры в рантайме:** зависимость от сети и квот Google, читерство, рассинхрон версий. Живые конфиги (remote config) — только если понадобятся после 1.0.
- SO остаются: код, тесты и префабы из серой коробки не меняются. Импорт делает `JsonUtility.FromJsonOverwrite(json, so)` — перезаписываются только поля, которые есть в JSON (числа), а `sprite`, префабы и прочие ссылки остаются из Inspector.
- Новый объект (строка с новым `id`) → импортёр создаёт SO-ассет `Data/<Вкладка>/<id>.asset`, ссылки на арт потом проставляются в Inspector. Строку убрали из таблицы → SO не удаляется, импортёр пишет предупреждение.

### 8.2 Таблица
Одна книга, вкладка = тип сущности = папка SO: `Heroes`, `Weapons`, `Enemies`, `Bosses` (фазы и атаки), `Passives`, `Statuses`, `Curses`, `Consumables`, `Loot` (дроп и цены), `Encounters` (волны), `Fusion` (правила сплава), `GameFeel` (hit-stop, мерцание, сплющивание, тряска), `Constants` (ключ–значение: крит, золото за этаж, лимит трупов…).
- Строка 1 — имена полей **точно как в SO** (`damage`, `critChance`, `attacksPerSecond`, …). Первый столбец — `id` (стабильный: `weapon.duelist_sabre`, `enemy.skeleton_archer`).
- Столбцы с `_` в начале (`_note`, `_ref`) — комментарии, в JSON не идут. Строки без `id` и с `enabled = FALSE` пропускаются.
- Перечисления — текстом (`family = Sword`, `rarity = Rare`), массивы — через `;`, ссылки на другие сущности — по `id`.
- Первичное заполнение: `Tools/data/so_to_csv` (Editor-меню «FotF/Данные/Экспорт в CSV») выгружает текущие SO, CSV вставляется в таблицу — числа из серой коробки не теряются.

### 8.3 Скрипт `Tools/data/sheets_to_json.py`
- Доступ v1: таблица «по ссылке — только просмотр», скачивание вкладок через `…/export?format=csv&gid=<gid>` без ключей. ID книги и gid вкладок — в `Tools/data/sheets.json`. Если таблица должна быть закрытой — v2 через сервисный аккаунт Google (ключ только в переменной окружения, не в репозитории).
- Валидация до записи (ошибка → код возврата 1, JSON не пишется): уникальные `id`, типы и диапазоны (`critChance` 0–1, урон ≥ 0), перечисления из списка, все ссылки на `id` существуют, обязательные поля заполнены. Схема полей — `Tools/data/schema.json` (генерируется Editor-меню из классов SO, чтобы не расходилась с кодом).
- Вывод: `Data/Balance/<вкладка>.json` = `{"version": N, "source": "<id книги>", "exported": "<дата>", "items": [...]}`; ключи и строки отсортированы → чистые диффы.
- Тест EditMode: каждый JSON проходит схему, каждый `id` из JSON имеет SO после импорта.

### 8.4 Сейвы (JSON)
Путь: `Application.persistentDataPath`. В сейве **только состояние и `id`**, никаких чисел баланса: поменяли урон в таблице — старые сейвы не ломаются.
| Файл | Что | Срез |
|---|---|---|
| `settings.json` | звук, язык, слайдер game feel, тряска, раскладка | да |
| `profile.json` | мета: кристаллы, открытые герои, дневник сплавов, статистика, состояние убежища | да |
| `run.json` | снимок забега для «продолжить» (герой, оружие как `WeaponInstance`, пассивки, проклятия, этаж, seed) | нет — 1.0 (§2) |
- Каждый файл: `{"saveVersion": N, ...}`; при чтении старой версии — цепочка миграций `Migrate_N_to_N+1` (EditMode-тест на каждую).
- Запись атомарно: `file.tmp` → проверка чтения → замена; предыдущая версия хранится как `file.bak`. Битый файл → загрузка из `.bak`, иначе новый профиль + сообщение игроку.
- Сериализация через State-модели (§2), View в сейв не попадает. Ручная правка сейва игроком не защищается (одиночная игра).

### 8.5 Порядок внедрения (на ноутбуке с Unity, по шагам B4)
1. Экспорт текущих SO в CSV → создать таблицу владельца.
2. `sheets_to_json.py` + `schema.json` + валидация (можно делать на Mac).
3. Editor-импортёр + авто-импорт + тест.
4. `profile.json`/`settings.json` с версиями, атомарной записью и тестами миграций.
