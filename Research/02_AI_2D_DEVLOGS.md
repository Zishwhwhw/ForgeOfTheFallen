## 1. Stop Generating Fake Pixel Art Game Sprites — Full Workflow (GPT Image 2.0, Nano Banana 2, Codex)
Chong-U — AI Oriented Dev · 08.05.2026 · 28:16 · https://youtu.be/nIAIxvNUrdU (автор продаёт скилы/курс)

- **0:07** Три главные проблемы AI-спрайтов: «mixels» (пиксели разного размера, размытые края), frame bleeding (кадр залезает в соседний), frame drift (ноги прыгают от кадра к кадру).
- **8:11** Эталонный кадр: 1024x1024, квадрат, плоский chroma-green фон, сильный силуэт, тёмный контур, не фотореализм. Размер должен быть большим — после snapping картинка сильно уменьшается.
- **9:11–12:12** Pixel snapping: open-source Sprite Fusion pixel snapper (K цветов + поиск краёв по двум осям → один настоящий пиксель на ячейку), потом nearest neighbor обратно до 1024. Автор обернул его в agent skill.
- **14:13–16:14** «Anchor»-цепочка: каждый результат → snap → upscale → становится reference для следующей генерации. Второй reference — checker-матрица 1024x1024 (чёрно-белые пиксели) держит «пиксельность». Режим edit, high quality.
- **18:14–20:14** Лист анимации: canvas 2048x1536 (ячейки 512x512, до 12 кадров, лучше 8–10). Ячейки меньше ~512 дают плохой snap. Рекомендованные кадры: idle 10, attack 8, hurt 6, jump 6, death 10. Два стиля промпта: покадровый и «motion guidance»; если один не работает, переключиться на другой.
- **21:15–25:19** Frame recovery (кроп по bounding box после chroma key вместо нарезки ровной сеткой) → выбор кадров цикла → второй snap → выравнивание по якорю (глаза на одной высоте; автор сделал frame aligner с onion skin) → итоговый лист (256x256 на кадр, 1280x512).
- **26:19–27:21** Walk cycle через image-модель «не получается»; нужен video-генератор (см. п. 2 и 5).

Для Scrapheart: цепочка anchor → snap → upscale и checker-reference напрямую решают «пиксель в 10 раз больше». Размер кадра 256 нам не нужен: генерировать крупно, snapping делать к целевой сетке (например 32/48/64 px высота персонажа при PPU 32).

## 2. How To Generate Consistent Game Assets with AI — GPT 5.4, Sora 2, Image 1.5, Codex CLI
Chong-U — AI Oriented Dev · 20.03.2026 · 41:45 · https://youtu.be/wO51cIue9xA (аффилиат)

- **6:04–10:08** Сначала mock-up игры, потом idle-кадр персонажа. Кадр генерируется крупно и **даунскейлится до 64x64** — этот низкоразрешённый кадр и есть «anchor image», всё остальное строится от него.
- **11:08** Покадровая генерация теряет консистентность (меняется цвет, высота, лицо). Простой idle лучше делать **Python/Pillow**: сдвигать пиксели anchor-кадра, без image-модели.
- **12:08** Приём: anchor увеличить на большой пустой canvas и просить image-модель дорисовать весь лист в одном вызове — консистентнее, чем кадр за кадром.
- **13:08–15:08** Normalization: равные интервалы кадров + нормализация по **медианной высоте персонажа**, а не по высоте кадра.
- **34:15–36:16** Реальный баг: crouch выглядел огромным, потому что нормализация масштабировала по высоте кадра (при поднятом мече высота растёт, при приседе падает). Исправление в skill: единый масштаб персонажа на все кадры.
- **16:09–20:10** Walk/run: image-модель не тянет; Sora 2 по одному anchor-изображению даёт лучше. Нужно обязательно передавать image reference. Дубли кадров и лишняя длина режутся скриптом.
- **23:10–25:12** Рабочий процесс агента: plan mode, одна и та же анимация в двух вариантах (image vs video), side-by-side в отдельной animation test scene, выбор лучшего глазами.
- **31:15** Все планы и промпты сохраняются в репозитории (plans/, prompts/), коммиты через lazygit — можно воспроизвести.

Для Scrapheart: нормализация по якорю/высоте тела (а не по bounding box кадра) — обязательное правило нашего pipeline; test-scene для сравнения вариантов анимации полезна и в Unity.

## 3. Building Diablo 2 with AI — 16 Directional Animated Sprites for an Isometric Game
DevDude · 30.05.2026 · 24:17 · https://youtu.be/h_8vcQp8jjQ (Sorceress Game Creation Suite — продукт автора)

- **0:00–2:00** Конвейер 3D→2D: референс персонажа (A-pose) → 3D-модель (Tripo/Meshy) → оптимизация 346k→200k треугольников (модель не идёт в игру, только для рендера).
- **3:00–5:03** Авто/ручной rig (маркеры pelvis, shoulders, elbows, wrists, knees, ankles), анимации текстом («person walks forward»), затем «smooth loop» — ghost frame и твининг последних кадров, чтобы убрать подёргивание на шве цикла. Анимации дешёвые: генерировать пачкой, выбирать.
- **8:04–10:06** Batch-конвертер 3D→2D: выбор ракурсов (пресет isometric 16 направлений, угол elevation настраивается, можно top-down), edge enhancement (контур), прореживание кадров (каждый N-й) для «2D-вида» и меньшего листа.
- **11:06** Генерируются normal maps (фейковое 2D-освещение) и universal JSON метаданных для кодингового агента.
- **12:06** Работа агентов: Opus для начальной архитектуры, потом более дешёвый агент (GPT 5.5 / DeepSeek) продолжает.
- **14:07–17:13** Одна анимация каста = start / middle (ping-pong loop) / end; один и тот же JSON обслуживает все 16 направлений, быстрые и channeled заклинания собираются из тех же кадров.

Для Scrapheart: это самый надёжный путь к единому масштабу и N направлениям при 3/4-виде: 3D-рендер гарантирует одинаковые пропорции. Минус — «сделано из 3D» стиль, нужен pixelate/snap в палитру Endesga 32.

## 4. The Holy Grail of Retro Game Dev — AI Pixel Art Generation Workflow
DevDude · 03.03.2026 · 10:37 · https://youtu.be/cPvsGXKYILs (аффилиат)

- **0:00–1:00** «True pixel» конвертер: на вход референс-картинка или видео; первым шагом chroma key (tolerance около 60 по опыту автора).

- **3:02** Ступени разрешения 16 / 32 / 48 / 64 / 96 px: чем выше, тем больше деталей, но придётся перенастраивать chroma key (теряются мелкие части, например нос).

- **6:03** Короткая длительность видео (Grok Imagine) → лучше зацикливается.
- **8:05** Можно увеличить размер палитры или поиграть с дизерингом; одну и ту же сцену (камень, луна, цветок, иконка меча) можно прогнать теми же настройками.

Для Scrapheart: конвертер с фиксированной сеткой и палитрой — тот же принцип, что snapping; нам нужен именно режим «палитра Endesga 32, фиксированная целевая высота». Инструмент платный (lifetime), цена в видео не названа.

## 8. How I Keep AI Pixel Art Monsters Consistent in Godot
After Work Game Lab · 24.11.2026 · 4:16 · https://youtu.be/uTGBSrBP9Xg

- **0:00–0:30** Причина проблемы: если просить AI рисовать спрайты по одному, он «заполняет кадр» — толщина пикселя, обводка и высота меняются каждый раз; текстовые подсказки не помогают.
- **1:02** Приём «scale ruler»: референс-лист — широкий плоский холст, герой слева (чёткий спрайт с нужной обводкой), справа пусто; для каждого нового врага: «героя слева не трогать, нового нарисовать справа на той же линии земли».
- **1:33–2:04** Так сгенерирован весь ростер: мелкие импы остаются мелкими, боссы пропорциональны (в промпте — «по шею выше героя»).
- **2:35** Проверка воспроизводимости: тот же лист + новый босс (тигр) → тот же масштаб и контур.
- **3:06** Сырой AI-спрайт всё равно нельзя в движок: выделить фон, snap к сетке 1:1 и заблокированная палитра; 2D lighting в движке склеивает слои.
- **3:36** Честные пределы: только статичные спрайты, результат плавает между запусками, ручная чистка остаётся.

Для Scrapheart: самый дешёвый способ сохранить относительные размеры врагов и игрока — эталонный лист с героем (в натуральную величину нашей сетки) в каждом запросе.

## 9. How to Generate Consistent Pixel Art for Games (PixelLab: style reference)

Для Scrapheart: набор референсов = наши утверждённые спрайты в нашем масштабе; из них можно «размножать» оружие и пропсы.

## 10. Tutorial: How to create tilesets using AI (PixelLab)
PixelLab · 12.02.2025 · 13:36 · https://youtu.be/D0uZTaHj0Do (интерфейс старой версии — возможны отличия)

- **8:05–12:06** Side-scroller-тайлы (платформа с небом); для нестандартного размера включить custom size (пример 80x64), итерации: сгенерированное → снова init image.

# Выводы для pipeline Scrapheart (из видео)

1. Любой AI-вывод проходит snap к целевой сетке и заблокированной палитре — иначе «mixels» (#1, #6, #8).
2. Масштаб держит эталонный лист с героем и/или anchor-кадр целевого размера (#1, #2, #8).
3. Анимации: простая — скриптом, сложная — video-модель или 3D→2D, затем нормализация по высоте тела и выравнивание по якорю (#1, #2, #3).
4. Для 3/4 top-down с несколькими направлениями 3D→2D конвертер даёт стабильность (#3), но нужен pixelate/snap в Endesga 32.
5. Агентам отдавать JSON/индекс ассетов (кадры, размер, PPU) и сохранять промпты в репо (#2, #3, #15).
6. Цены в видео нестабильные (акции, лимиты) — окончательные брать из актуальных страниц (06_ASSET_PIPELINE_MCP.md).
