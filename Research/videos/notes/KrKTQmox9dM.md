# Вайбкожу свою игру для Steam ч.11
https://youtu.be/KrKTQmox9dM

(Игра автора: 2D, Godot, автоматизация + крафт + культист-некромант; GDD в Obsidian. Ниже только применимое к чужому проекту.)

## 1. Архитектура кода
- **Закладывай ограничения построек в правила (строить только на конвейерах) и сверяй реализацию с GDD.** — автор обнаружил, что постройки встают не так, как задумано («все постройки крепятся к конвейеру»), и поправил текст GDD под принятое решение. [00:14]
- **Делай чит-режим для тестирования (F2, жёлтая плашка «ЧИТ», постройки ставятся сразу готовыми и бесплатными, инвентарь не трогается).** — без читов тестировать цепочки было «неприятненько»; чит-методы сделал Claude, пока шёл стрим. [00:08]
- **Описывай базовый UX как правила в GDD: авто-коннект конвейера к входу/выходу, поворот на R, сброс выбранной постройки при входе в режим сноса и наоборот.** — найденные при плейтесте дыры сразу превращаются в формулировки-баги для агента. [00:11]

## 2. Работа с ИИ-агентами
- **Играй в то, что агент собрал, с читами, и сразу пиши фидбек агенту.** — задача на стрим: поиграть во все механики с читами; багов находилось много (улетевшая постройка, одноразовое заклинание, слои). [00:03]
- **Описывай баг как желаемое поведение («заклинание не должно быть одноразовым; один раз скрафтил — используешь постоянно»).** — автор нашёл, что баф расходуется, и дал агенту правило. [00:26]
- **Мелкий неудобный UX не чини сейчас: пометь «отдельной проходкой переделаем весь интерфейс».** — крафт-UI неудобный, но полный проход по интерфейсу будет позже, поэтому не критично. [00:21]
- **Поручай агенту рутину окружения одним промптом (починить автозапуск скрипта, убрать приложения из автозагрузки).** [00:37]
- **Поручай агенту писать инструменты под себя: нормальные таблицы в Obsidian — один промпт; плагин «холст» (Canvas) для Obsidian — два промпта.** — на базе open-source Obsidian; холст со ссылками на заметки GDD, скриншоты из буфера, копия по Alt+перетаскивание. Фичи дописывались прямо на стриме просьбами агенту (хоткей, слои, стиль стрелок по умолчанию, UX контекстного меню). [00:09]
- **Для идей по контенту давай агенту куски графа: «здесь локация, 3 моба и 2 месторождения — что сюда логично поместить?» — затем отбирай и фильтруй по фантазии.** — когда с идеями туго, нейронка накидывает варианты, ты выбираешь и сшиваешь с нарративом. [01:16]
- **Выбирай модель/effort под задачу: слабая модель на низком effort — для простых быстрых задач; сложное — сильной моделью на высоком effort.** — слабая модель даже на высоком effort сложную задачу не решит. [02:01]
- **Сложные задачи (спрайты, анимация) отдавай самой сильной модели (Fable 5.2), рутину — Opus.** — автор использует Opus по умолчанию, Fable — для спрайтов; после 2-3 промптов фидбека анимация персонажа заметно улучшилась. [01:24]
- **Не ждёшь результата с первого промпта: итерируй с агентом фидбеком и чисти pipeline.** — «работа достаточно простая, нет безысходности; просто посидеть, давать фидбек». [01:25]
- **При подписке за 20$ можно начать, но серьёзный объём не потянуть; главный пассивный расход лимитов — чтение контекста.** — ответ зрителю по лимитам. [00:29]
- **Ссылки на GDD в формате Markdown — лучший формат для нейронок.** — Obsidian: ссылки между заметками, картинки как ссылки на png (агент их тоже достаёт). [02:19]
- **Локализацию держи в уме: она затратная по лимитам.** [00:29]

## 3. Геймдизайн и GDD
- **Строй дизайн как фреймворк сверху вниз: Концепт (фантазия + жанр) → ощущения/потребности → активности → цель/действие/награда → виды контента → прогрессия возможностей и контента по этапам → граф игры.** — каждый нижний слой проверяется на соответствие верхнему, при необходимости возвращаешься и правишь верхний. [01:20]
- **Формулируй фантазию игрока в одной строке в концепте.** — «убийца чудовищ» (Witcher); фантазия — гипотеза о том, что игрок захочет прожить, и может оказаться ошибкой. [00:50]
- **Раскладывай фантазию на ощущения, а ощущения привязывай к потребностям (power, curiosity, completion и др., 12 мотиваций игроков).** — у автора: управление культом → власть и стратегия; тёмная магия → любопытство и исследование; завершённость; месть. [00:55]
- **Выводи активности из двух источников: жанр (must-have, напр. автоматизация) и фантазия.** — любая идея, не проходящая фильтр «жанр или фантазия», режется (фермерство, шутер-геймплей отброшены): это защита от feature creep. [01:01]
- **Для каждой активности прописывай цель, действия, награду, затем механики и виды уникального контента.** — бой → мобы, боссы, ресурсы с мобов, оружие, заклинания; исследование → крафты и исследования, открывающие крафты. [01:02]
- **Проверяй свои активности на «фейковое оправдание»: нужна ли она ради фантазии или только ради жанра.** — добыча руками нужна для контраста с эпохой до автоматизации; руины алтаря (restoration) — реюз «починить сломанное и вернуть былое величие». [01:03]
- **Распиливай игру на этапы по боссам (онбординг + до босса 1 + до босса 2 + до босса 3).** — 5 часов игры, 3 босса, этапы по 1–1,5 часа; онбординг вынесен отдельно. [01:06]
- **Строй таблицу «активность x этап → возможности / контент».** — возможность = новый юзкейс (что игрок может делать впервые), контент = новые сущности; чтобы игра была интересна на дистанции, каждому этапу надо подкидывать новое. [01:09]
- **Не всем активностям нужен рост возможностей: диалоги, квесты, мусор — системы вторичные.** — квесты вываливают все возможности в начале, контент зависит от остальных систем. [01:12]
- **Ставь цифры «как чувствую» (референсы, опыт), потом конкретизируй в докe контента.** — «4 новых спрайта мусора» → затем решаешь, какой это мусор. [01:13]
- **Всегда продумывай первый час игры через действия игрока, а не через системы.** — «что игрок делает, какие этапы, куда приходит»; идти от точки B назад; затем оборачивать в ТЗ для агента. [00:41]
- **Раскладывай любую игру в путь точка A → точка B как граф зависимостей с нелинейностью (веер).** — пример Minecraft: Эндердракон ← портал Энда ← жемчуг/палки ← Ад ← обсидиан ← алмазы ← железо ← камень ← дерево. [00:43]
- **Строй граф игры: узлы — задачи игрока, локации, блокеры, лут, точки интереса, мобы, боссы/арены, месторождения; на стрелках — этапы открытия.** — в графе сразу смешиваются level design, экономика, нарратив, UI; всё сводится к задачам игрока. [01:49]
- **Присваивай ID локациям, боссам, POI по схеме «локация.номер» (2.1.1).** — упрощает управление. [01:39]
- **Опциональные вещи (мусор для уборки) не клади на граф критического пути.** — мусор разместишь на уровне level design; не делай его блокером. [01:46]
- **Показывай игроку долгосрочную цель заранее (карта дальних локаций).** [01:39]
- **Расширяй игру вглубь функциями в рамках старого контента, а не только новыми системами или реколором.** — три способа: новые системы (редко, решается на концепте), линейный контент (слитки железа → стали → титана, меняется только число и скин), новые функции старого контента (Satisfactory: постройки с 1/2/4 входами, развилки, поезда). Лучший вариант — третий; линейный контент нужен, но не единственный. [02:04]
- **Вширь = больше контента, вглубь = больше связей между системами; новые активности вглубь имеют предел адекватности.** [02:04]
- **Не пиши механики хаотично «что круто, то пихаем».** — автор: такой подход нерабочий, бесконечный feature creep, непонятно, что приоритетнее; поэтому ввёл фреймворк. [00:27]
- **Люди играют ради ощущений, не ради механик или контента.** — геймдизайн = дизайн ощущений (player-centric, ссылка на Game Design Skills). [00:48]
- **Проектируй UI книги исследований по референсу (My Time at Portia: чертежи).** — страницы с графом исследований и исследованием предметов, заметки-лут открывают исследования; игрок носит книгу (Некрономикон) с собой. [01:53]
- **Не заставляй возвращаться к станции исследований: книга всегда при игроке.** [01:57]
- **Эпичные моменты (смена тела) делай долгими и заметными.** — крафт тела намеренно долгий («момент важный для игрока»), анимация щелчка Таноса. [00:22]
- **Не выдавай все фичи сразу: часть (спринт/дэш) можно спрятать за телом высшего уровня.** — каждое тело должно иметь логичное развитие. [00:23]
- **Блокеры к новым локациям делай через лут боссов и апгрейд алтаря (T1 восстановление → T2 через лут босса).** [01:59]

## 4. Арт и ассеты
- **Арт откладывай максимально: сначала геймдизайн, потом пиксель-арт.** — пиксель-арт нерешённая задача для нейронок, придётся сидеть и итерировать. [01:22]
- **Для нейро-анимации пиксель-арта проси агента «топ-5 способов», пусть ищет в интернете, как делают другие.** — готового решения нет; ресёрч + фидбек. [01:21]
- **⚠ не сработало: промпт «сделай классные спрайты и анимацию» одним-двумя запросами в Fable.** — получилось «говнисто»; потом после нескольких промптов ноги пофиксились, но новый персонаж по тому же pipeline вышел «вялый». [00:30]
- **⚠ не сработало: локальные модели для пиксель-арт-анимации.** — «жрут железо, и не лучше платного Claude». [01:22]
- **Гипотеза: самый жизнеспособный pipeline — 3D-модель + анимация, затем рендер в 2D спрайты/пиксель-арт шейдером с аутлайном (как делали в Dead Cells).** — проблема перенесена на качество 3D-анимации нейронкой (бег, атаки, оружие). [01:26]
- **Ориентируйся на референсы анимации (пример игры с шортсов (название в расшифровке неразборчиво): VFX не пиксельные, анимации персонажа во многих направлениях).** — арт-дирекшн референса; воспроизвести нейронкой пока непросто. [00:31]
- **Если идеал недостижим — иди на компромисс: простые анимации, меньше кадров.** — «будем делать какой выйдет, выжму максимум». [00:34]
- **Нейронками закрывай арт целиком; художника не ищи (цель автора).** [00:33]
- **Звук: часть ассетов бери готовыми (free sound), музыку тестируй через Suno с промптом стиля.** — музыку начни с простой мелодии/мотива и скорми Suno; проверь, не надоедает ли. [00:07]
- **Чтобы музыка не надоедала: спроси нейронку, как устроена музыка в референсах, выпиши закономерности, сделай свою и проверь.** [00:06]
- **Пиксельный шрифт в пиксельной игре лучше, чем «плохой» непиксельный.** — мнение автора (Minecraft). [00:36]
- **Размер тайла определи заранее.** — зритель указал, что в игре он не определён. [00:52]

## 5. Контент и баланс
- **Для контента строй схемы и считай количество: «2 локации, 3 моба, 2 месторождения» на этап, а не рисуй детали сразу.** [01:16]
- **Заклинания крафти и используй как постоянный предмет, не расходуемый.** [00:26]
- **Оценивай кривую роста количества возможностей по этапам (онбординг быстрый, потом свободнее): так в Cyberpunk первые 5 часов с Джеки, потом открывается весь город.** [01:07]

## 6. Продакшн и Steam
- **Фиксируй дедлайн и честно считай часы: за 1,5 месяца автор потратил ~25 часов (10 стримов по ~2 ч), 4 ч в неделю — мало, поэтому стримы чаще.** — на 2 месяца заявлено «сделать игру»; осталось 2 недели. [00:01]
- **Проверка страницы Steam занимает дольше заявленного.** — обещали 15 рабочих дней, теперь 45; не рассчитывай на день в день. [00:28]
- **Игра, готовая к релизу через неделю, должна быть готова неделей раньше.** — совет зрителя. [00:28]
- **Раздел «использование ИИ» на странице Steam: попроси нейронку написать и согласуй с формой.** — автор не знает заранее, что именно писать. [00:35]
- **Не жди денег: первая игра — для опыта, вишлистов и понимания, почему идея не зашла.** — если не зайдёт, разбираешься, почему, и делаешь следующую. [01:05]
- **Для маркетинга (вишлисты) изучай чаты и разборы маркетологов под Steam; ориентиры: бесплатный MVP на itch за 12 дней — 3 500 просмотров, медиана важна.** — пример зрителя; автор советует смотреть материалы Ярослава Шалашова. [00:35]
- **Паблишеру важны команда и кейсы; соло-геймдизайнер с нейронками — риск для него.** — автор в паблишера пока не идёт. [02:02]
- **Налоги: физлицо в Steamworks, платишь налог по обычным правилам своей страны; с ИП на выплаты — налог на ИП.** [00:36]
- **Полный цикл разработки по фичам: ТЗ → сырая фича → плейтест → фикс → полишинг (финальный арт) → галочка; когда у всех фич галочки, общий playtest и релиз.** [00:38]
- **Финальные этапы: полишинг UX, активностей/геймплея, визуала, нарратива, локализация, потом Steam-страница, трейлер, картинки.** [02:18]

## 7. Ошибки и антипаттерны
- **Не плодить идеи механик без фильтра: feature creep.** [00:27]
- **Не оставлять игру на «ТЗ как набор фич»: нужна динамика, а не статичный список.** — по отдельности продумать кор-луп, прокачку, бой легко; сложно, чтобы это работало как игра, в которую интересно играть. [00:40]
- **Не делать контент линейным реколором везде.** — одинаковый паттерн выдачи контента не всегда интересен (кроме инкрементальных игр). [02:07]
- **Нейронка не делает хороший полишинг с одного промпта; с анимациями беда, с 3D лучше, но тоже есть вопросы.** — спрайтовые анимации нейронкой тяжело; с одного промпта хорошего полишинга нет. [00:39]
- **Не пользуйся DeepSeek для кода (совет зрителя): Claude для логики, GPT для визуала и фронта.** — мнение из комментариев, автор согласен только в том, что другие модели не нужны для кода. [02:03]
- **Заблокированный Claude/VPN: у автора нет решения, зрители используют VPN без приложения.** [01:27]

Инструменты: Claude Opus (основная разработка, GDD), Fable 5.2 (сложные задачи, спрайты/анимация), Godot (движок), Obsidian + собственный плагин-холст (GDD, граф игры), Suno (тест музыки), Steamworks (страница, ревью), itch.io (альтернативная площадка), ChatGPT/GPT (визуал, фронт — по словам автора, ходят слухи о новой модели), DeepSeek (не рекомендовано), Game Design Skills (сайт по player-centric дизайну), YouTube/Telegram (стримы, плагин).
